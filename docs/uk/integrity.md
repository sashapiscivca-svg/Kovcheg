# Цілісність і підписи модулів

[English](../en/integrity.md) · [Зміст документації](README.md)

Модуль (база знань), який хтось змінив — навмисно чи через пошкодження диска, — може дати хибні вказівки під час кризи. Ковчег робить такі зміни видимими.

## Як це працює

- Після кожного збирання `manifest.json` фіксує хеш SHA-256 і розмір кожного файлу модуля (`kovcheg.db`, `dense.f16.npy`, `sparse.npz`).
- Якщо існує `keys/private_key.pem`, засіб збирання підписує точні байти `manifest.json` ключем Ed25519 і записує `manifest.sig`. Маніфест також фіксує ідентифікатор ключа підписанта (перші 16 шістнадцяткових символів SHA-256 відкритого ключа).
- Застосунок відкриває модулі суто для читання, тож звичайне використання ніколи не змінює жодного файлу.
- Перевірка спершу звіряє підпис, потім розміри файлів, потім (у глибокому режимі) SHA-256 кожного файлу. Результат успішної глибокої перевірки кешується в `<module>/.verified.json` за розміром і часом зміни кожного файлу, тож її не повторюють під час кожного запуску. На носіях лише для читання кеш не використовується, і перевірка виконується знову.

## Стани

| Стан | Значення | Що робить інтерфейс |
|---|---|---|
| **valid** | підпис довіреним ключем, файли цілі | зелена позначка |
| **unsigned** | підпису немає, файли відповідають маніфесту | нейтральна позначка; прийнятно для модулів, які ви зібрали самі |
| **untrusted** | дійсний підпис ключем, якого немає у вашому сховищі довірених ключів | бурштинова позначка; перевірте, хто створив модуль |
| **INVALID** | файл змінено або він відсутній, або підпис не збігається | червоне попередження; модуль типово не вибрано |

## Ключі та довіра

```bash
kovcheg keygen                 # keys/private_key.pem (права 0600) і keys/public_key.pem
kovcheg sign first-aid         # підписати наявний модуль
kovcheg verify                 # глибока перевірка всіх модулів; код завершення 1, якщо хоч один INVALID
kovcheg verify first-aid --quick
```

Довіреними відкритими ключами є ваш власний (`keys/public_key.pem` або виведений із приватного ключа) і кожен `keys/trusted/*.pem`. Щоб поширювати модулі, опублікуйте свій `public_key.pem` через канал, якому ваші користувачі вже довіряють, наприклад надрукованим на папері чи передавши особисто, і попросіть їх покласти його в `keys/trusted/`.

## Чого підпис не робить

- Він не доводить, що вміст правильний, актуальний чи безпечний. Він доводить лише, хто зібрав модуль і що відтоді його не змінювали.
- Кеш перевірки може обдурити зловмисник, який змінить файл, зберігши його розмір і відновивши точний час зміни. `kovcheg verify` завжди повністю перераховує хеші, тож на нього це не впливає.
- Будь-хто з вашим приватним ключем може підписувати від вашого імені. Зберігайте його офлайн, майте резервну копію й ніколи не кладіть його в набір, який поширюєте.
