# Моделі

[English](../en/models.md) · [Зміст документації](README.md)

Ковчег використовує до трьох моделей. Кожна з них необов'язкова, кожна — це локальний файл або тека, які ви завантажуєте один раз, і Ковчег ніколи нічого не завантажує сам.

| Компонент | Без нього | З ним |
|---|---|---|
| **Модель ембедингів** (BGE-M3) | лише пошук за ключовими словами (BM25); запитання мусить мати спільні слова з відповіддю; міжмовного пошуку немає | семантичний і багатомовний пошук, а також навчені лексичні ваги (розріджені) |
| **Реранкер** (BGE reranker v2-m3) | кандидати впорядковуються за об'єднаними оцінками пошуку | крос-енкодер повторно читає найкращих кандидатів разом із запитанням; кращі верхні результати й надійний сигнал «немає доказів» |
| **Мовна модель** (будь-яка інструктивна GGUF) | відповідь — це список знайдених уривків | коротка письмова відповідь із посиланнями на уривки у вигляді [1], [2] |

## Завантаження (на комп'ютері з інтернетом)

За допомогою інструмента командного рядка Hugging Face (`pip install huggingface_hub`):

```bash
huggingface-cli download BAAI/bge-m3 --local-dir models/bge-m3 --exclude "onnx/*" "imgs/*"
huggingface-cli download BAAI/bge-reranker-v2-m3 --local-dir models/bge-reranker-v2-m3
huggingface-cli download Qwen/Qwen2.5-1.5B-Instruct-GGUF qwen2.5-1.5b-instruct-q4_k_m.gguf --local-dir models
huggingface-cli download bartowski/Phi-3.5-mini-instruct-GGUF Phi-3.5-mini-instruct-Q4_K_M.gguf --local-dir models
```

Або за допомогою `git` (потрібен Git LFS): `git clone https://huggingface.co/BAAI/bge-m3 models/bge-m3`.

Потім скопіюйте теку `models/` на офлайн-комп'ютер. Запустіть там `kovcheg doctor`: команда покаже, які моделі знайдено, їхні розміри й рівень, який підтримує ваше обладнання.

## Вибір мовної моделі

- Малі моделі (1–2 млрд параметрів) швидко працюють на міні-ПК (приблизно 5–15 токенів за секунду на 4-ядерному процесорі, тож відповідь на 300 токенів займає 20–60 с), але частіше неправильно читають уривки. Середні моделі (3–8 млрд) краще читають, але працюють у 2–5 разів повільніше й потребують більше оперативної пам'яті.
- Надавайте перевагу моделям, які добре підтримують мови ваших документів і запитань. Багатомовна якість малих моделей буває різною, тож перевіряйте на власних запитаннях (`kovcheg eval` вимірює якість пошуку; вибірку відповідей прочитайте самі).
- Квантування Q4_K_M — добрий типовий вибір. Q5_K_M або Q8_0 трохи надійніше читають числа, але потребують більше оперативної пам'яті.
- Перевірте ліцензію: Qwen2.5-3B-Instruct (ліцензія Qwen Research), моделі Llama і Gemma мають умови, які можуть не дозволяти вашого способу використання.

## Бюджет пам'яті

Орієнтовно використання оперативної пам'яті ≈ модель ембедингів (BGE-M3 ≈ 2,3 ГБ у fp32 на CPU) + реранкер (≈ 2,3 ГБ, лише якщо ввімкнено) + розмір файлу GGUF + контекст (≈ 0,3–1 ГБ для 4–8 тис. токенів) + 0,3 ГБ. Вектори модуля відображаються в пам'ять (memory-mapped) і не повністю зараховуються до використання оперативної пам'яті.

На комп'ютері з 8 ГБ не вмикайте всі три великі моделі одночасно. У [прикладі для рівня A](../../examples/tier-a-minipc.toml) реранкер вимкнено.

## Установлення бібліотек для інференсу

```bash
pip install -e ".[embed]"     # FlagEmbedding + PyTorch, для BGE-M3 і реранкера
pip install -e ".[llm]"       # llama-cpp-python, для моделей GGUF
```

У Linux без GPU спершу встановіть збірку PyTorch для CPU. Вона приблизно вдесятеро менша за типову збірку з CUDA: `pip install torch --index-url https://download.pytorch.org/whl/cpu`. `llama-cpp-python` компілюється з вихідного коду, якщо для вашої платформи немає готового wheel-пакета. Готові wheel-пакети для CPU описано в документації цього пакета.
